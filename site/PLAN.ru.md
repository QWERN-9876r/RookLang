[English](PLAN.md) · **Русский**

Рабочий документ. Составлен 11 ноября 2026 года по итогам обсуждения и прототипа.

- **Утверждённый прототип:** <https://claude.ai/artifact/MPCWCiMj1Wynka615Jq8pK>, версия 3, страница

## 1. Что строим

Сайт, на котором программу видно. Раздел о потоках открывается сценой: доска уходит в перспективу,
горутины стоят на ней ладьями, сообщения ходят по горизонтали. Под сценой остаётся текст раздела.
Код на сцене живой, рядом показан JS, в который он компилируется.

Что уже решено:

| Тема                | Решение                                                                                                                                                       |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Концепции           | Живая дока, видимый рантайм, переводчик (JS, Go → Rook), партия (карта языка и прогресс).                                                                     |
| Метафора            | Вертикаль доски — горутина или канал. Время уходит вдаль. Сообщение — ход по горизонтали. Ожидание — пунктир и кольцо вокруг ладьи. Дедлок — пат.             |
| Экран               | Одна сцена: доска, карточка кода слева, одна подпись к текущему ходу, линия ходов. Без панелей, списков шагов и легенд.                                       |
| Движение            | Каждое движение что-то значит. Декоративная анимация допустима только на главной.                                                                             |
| Ладьи               | Объёмные. Новая падает с неба, отправитель бросает значение, получатель ловит с отдачей, ждущая стоит в кольце, закончившая уходит в доску.                   |
| Что убрано с экрана | Карта языка, переключатель «я из JS / Go», задачи, выбор числа горутин. Они возвращаются отдельными сценами в том же стиле (этапы 5 и 7), а не на этот экран. |

## 2. Устройство сайта

Адреса страниц не меняются: пять страниц в двух языках, у разделов гайда и примеров свои адреса.

| Страница               | Что меняется                                                                                                          |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------- |
| Главная                | Первый экран — та же сцена с короткой программой в цикле вместо декоративных дорожек.                                 |
| Гайд, `docs/<раздел>/` | Сверху сцена раздела, ниже текст как сейчас. У примера в тексте кнопка «Сыграть на доске»: она загружает его в сцену. |
| Гайд, `docs/`          | Карта языка в виде доски с прогрессом (этап 7).                                                                       |
| Примеры                | Новый стиль. Вкладка «Без Rook» остаётся.                                                                             |
| Песочница              | Вкладка «Доска» рядом с результатом и консолью: любую программу с каналами можно посмотреть по ходам.                 |
| Roadmap                | Только новый стиль.                                                                                                   |

Сцена есть не у каждого раздела. Раздел без сцены выглядит как сейчас, в новом стиле.

Видов сцен три:

| Сцена   | Что показывает                                                               | Разделы гайда                                                                  |
| ------- | ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| Партия  | Горутины и каналы по ходам. Это прототип.                                    | async, goroutines, channels, select, streams, topics, channel-objects, signals |
| Импульс | Изменение состояния бежит к узлам DOM, в превью вспыхивает обновлённый узел. | state, components, markup, mount                                               |
| Перевод | Код Rook превращается в JS (или в «как это было бы в Go»).                   | Разделы о языке; по желанию, текст остаётся главным                            |

## 3. Сцена: как устроена

Сцена — это проигрыватель трассы:

```text
трасса (список событий) → состояние в момент T → кадр на canvas
                                               → подпись хода, строка кода, линия ходов в DOM
```

- **T — дробный номер хода.** Всё на экране вычисляется из T, как в прототипе. Поэтому перемотка
  вперёд и назад работает сама, а состояние можно проверять тестами без canvas.
- **Сцена не знает про Rook.** Она получает трассу. Откуда трасса взялась (записана при сборке или
  пришла из живого запуска), ей неважно.
- **Canvas 2D, без библиотек.** Проекцию доски прототип считает сам, этого достаточно.
- **Код сцены — на Rook,** в `site/src/stage/`: сайт сам программа на Rook. Один файл на область,
  не длиннее 400 строк.

| Файл          | За что отвечает                                                                |
| ------------- | ------------------------------------------------------------------------------ |
| `trace.rk`    | Типы событий и трассы.                                                         |
| `state.rk`    | Состояние в момент T: статусы горутин, буфер, значение в пути. Чистые функции. |
| `camera.rk`   | Проекция доски и размеры под ширину экрана.                                    |
| `board.rk`    | Клетки, горизонт, пыль.                                                        |
| `lanes.rk`    | Дорожки горутин и мосты сыгранных ходов.                                       |
| `rooks.rk`    | Форма ладьи и её движения по событиям.                                         |
| `pieces.rk`   | Значение в пути, плитки буфера, кольца каналов, подписи вертикалей.            |
| `player.rk`   | Время: игра, пауза, цикл, перемотка, клавиши.                                  |
| `captions.rk` | Подпись хода по событию. Тексты лежат в `site/src/en/` и `site/src/ru/`.       |
| `stage.rk`    | Компонент `<Stage>`: canvas, карточка кода, подпись, линия ходов.              |

Правила для сцены:

- Рисует, только когда видна на экране и вкладка активна.
- При `prefers-reduced-motion` показывает статичный кадр, перемотка по ходам остаётся.
- На телефоне сцена идёт блоком над подписью и кодом, как в прототипе.
- Текст (подпись хода, код, заголовок) лежит в HTML, а не в canvas: его видят поиск по гайду,
  `scripts/prerender.ts` и скринридеры. Подпись хода объявляется через `aria-live`.
- Код сцены загружается отдельно и только на страницах, где сцена есть.

## 4. Настоящие ходы: трассировка рантайма

В прототипе ходы считает маленький планировщик на странице. На сайте их должен отдавать рантайм
Rook, иначе сцена показывает не то, что делает программа.

Что известно о рантайме и что из этого следует:

- Состояние канала живёт в потоке, который его создал; операции других потоков приходят к нему
  сообщениями (`src/runtime/chan.js`, `threads.js`). Значит, у событий одного канала есть общий
  порядок: его видит поток-владелец.
- Песочница уже пересылает `console.log` из воркеров через `BroadcastChannel`
  (`site/src/sandbox.rk`). События трассы можно пересылать так же.

Черновик устройства (уточняется на этапе 2):

- **Точка подключения** — значение в `globalThis` под `Symbol.for('rook.trace')`, как у остальных
  общих вещей рантайма. Нет значения — нет трассировки.
- **События:** горутина запущена, горутина закончилась, канал создан, операция ждёт, значение
  передано (сразу в руки, в буфер, из буфера), канал закрыт, строка консоли.
- **Строка кода и имя функции** для каждого события. Рантайм их не знает, поэтому нужна опция
  компилятора `trace`: с ней генератор передаёт место операции в вызов рантайма. Это не синтаксис
  языка, и мейнтейнер её выбрал (решение 4).
- **Кто сделал ход.** Поток пула может держать несколько вызовов, ждущих в `await`. В режиме
  трассировки пул должен давать каждой горутине свой поток, тогда поток и есть горутина. Проверить
  по `src/runtime/go.js`.
- **Пат.** Все известные горутины ждут на каналах, новых событий нет: сцена показывает пат. В
  roadmap это «Phase 3 — debugging goroutines» («A deadlock is not reported»), так что точка
  подключения пригодится и там.
- **Трассы примеров записываются при сборке** и попадают в страницу вместе с кодом примеров, как
  `virtual:examples`. Сцена играет сразу, без компиляции в браузере. Порядок ходов в настоящих
  потоках не определён, поэтому для записи нужен детерминированный запуск. Кандидат — `$$goHere`
  (горутина в том же потоке); проверить, подходит ли.
- **Живой запуск** нужен, когда читатель поменял код: компилятор в браузере, запуск с
  трассировкой, новая партия.
- **Цена без трассировки:** не больше одной проверки на операцию. Размер рантайма замерить до и
  после и записать сюда.

## 5. Визуальная система

Сейчас тема сайта (`site/ui/theme.module.css`) — чёрный фон, тонкие линии, белый текст и оранжевый
цвет ладьи. Новая тема продолжает её, а не заменяет:

- **Фон** — тёплый чёрный вместо чистого, со светом у горизонта.
- **Свет ладьи** — тот же оранжевый, `#f59e2a`: он светится (дорожки, оператор `<-`, активная
  строка), а не просто красит.
- **Цвета горутин:** оранжевый у `main`, бирюзовый и сиреневый у следующих. Это данные, а не
  украшение: у ладьи, её дорожки, её точек в коде и её штриха на линии ходов один цвет.
- **Красный** — только пат и ошибки.
- **Шрифты:** см. решение 2. Любой новый шрифт подключается так же, как Geist: пакетом
  `@fontsource`, без внешних сервисов.
- **Тема только тёмная,** как сейчас.
- **Лигатуры в коде выключены:** `<-` и `<=` должны выглядеть так, как их печатают.

## 6. Этапы

Размер: S — до дня работы, M — несколько дней, L — неделя и больше. Каждый этап заканчивается
рабочим сайтом в обоих языках.

### Этап 0. Решения (S) _(пройден)_

Мейнтейнер ответил на открытые вопросы; ответы записаны в разделе 9.

### Этап 1. Движок сцены и пилот «Каналы» (L)

Цель: раздел `docs/channels/` выглядит и двигается как прототип. Рантайм не трогаем.

1. Перенести прототип в `site/src/stage/` на Rook, разбив по файлам из раздела 3.
2. Трассы пилота — данные, снятые с планировщика прототипа, для буфера от 0 до 4. Живое число в
   коде переключает между ними.
3. `<Stage>` в разделе «Каналы», английском и русском. Подписи ходов — в строках обоих языков.
4. Токены сцены в теме сайта.
5. Тесты: состояние по T на трассах пилота (статусы, буфер, пат); сайт компилируется; сборка с
   `scripts/prerender.ts` проходит и пишет текст сцены в HTML.

Готово, когда:

- на dev-сервере раздел совпадает с прототипом на десктопе и на телефоне;
- при `prefers-reduced-motion` виден статичный кадр, перемотка работает;
- `npm run check` и `npm run site:build` проходят.

### Этап 2. Настоящие ходы (L)

Цель: пилот играет то, что сделал рантайм.

1. Точка подключения трассировки в `src/runtime/`; `src/runtime/sources.ts` обновляется через
   `npm run format`.
2. Опция компилятора `trace` (решение 4).
3. Запись трасс примеров при сборке. Пилот переходит на неё, данные этапа 1 удаляются.
4. Живой запуск в браузере после правки кода.
5. Обнаружение пата.
6. Тесты рантайма: события отправки, получения, закрытия и запуска горутины, их порядок, пат.

Готово, когда:

- смена буфера на 1 показывает пат из настоящего запуска;
- без опции `trace` сгенерированный код не меняется (`tests/output/` без изменений);
- прирост размера рантайма замерен и записан в раздел 4.

### Этап 3. Главная и стиль всего сайта (M)

Цель: весь сайт в одном стиле, первое впечатление — сцена.

1. Первый экран главной — сцена с короткой программой в цикле (вместо дорожек в
   `site/src/home/hero.rk` и `lanes.rk`).
2. Тема `site/ui/` в новых токенах: шапка, навигация гайда, карточки кода, страница примеров,
   песочница, roadmap.
3. Новые картинки для ссылок: `npm run site:images`.

Готово, когда все пять страниц в обоих языках в одном стиле, а Lighthouse не хуже, чем до начала.

### Этап 4. Сцены потоков и «Доска» в песочнице (L)

| Раздел          | Что нового на доске                                                                                              |
| --------------- | ---------------------------------------------------------------------------------------------------------------- |
| goroutines      | Копии аргументов летят к новой ладье, результат возвращается ходом. `go for`: несколько ладей на частях массива. |
| select          | Перед ладьёй подсвечены линии всех веток, сыграет одна.                                                          |
| streams, topics | Один ход расходится ко всем подписчикам.                                                                         |
| signals         | Отмена — взятие: ладья гаснет и уходит с доски.                                                                  |
| async           | Задачи одного потока ходят по очереди на одной вертикали.                                                        |

Ещё в этом этапе: кнопка «Сыграть на доске» у примеров и вкладка «Доска» в песочнице.

Готово, когда у каждого раздела группы Concurrency есть сцена в обоих языках, а программа с
каналами из песочницы играется на доске.

### Этап 5. Переводчик (M)

1. Вкладки карточки кода: Rook, JS на выходе, «Без Rook» (файлы `site/examples/js/<имя>/`).
2. Переключатель «я из JS / TS / Go», выбор запоминается. В тексте разделов — врезки для
   пришедших из Go. Это новый текст на двух языках.
3. Морфинг кода при переключении Rook → JS: общие токены остаются на месте, остальные переезжают.

### Этап 6. Сцена «Импульс» (L)

Реактивность: изменение состояния бежит импульсом к узлам DOM. Нужна трассировка
`src/runtime/signals.js` и `markup.js`. Перед реализацией — отдельный прототип-артефакт, который
утверждает мейнтейнер, как это было со сценой «Партия».

### Этап 7. Карта, прогресс, задачи (M)

1. `docs/` открывается картой языка: клетка — раздел, ладья стоит на текущем, пройденное отмечено.
   Прогресс хранится в браузере.
2. Задачи на сцене («мат в один ход»: убрать пат, поменяв одно число) с проверкой по трассе.

Сначала прототип.

### Этап 8. Сквозное приложение (по отдельному решению)

Гайд строит одно приложение от `hello` до серверных компонентов. Это переписывание текста 35
разделов на двух языках. Решать после этапа 7.

## 7. Как работаем

- Новый вид или новый тип сцены сначала делается прототипом-артефактом и утверждается, потом
  переносится в сайт.
- Английский и русский меняются в одном изменении: строки, тексты разделов, примеры.
- Ни один файл кода не длиннее 400 строк; делить по ответственности заранее.
- После каждого этапа: `npm run check`, `npm run site:build`, показ на dev-сервере.
- Коммит и push — только по просьбе. Push новой версии в `main` публикует сайт, поэтому
  незаконченный этап в `main` не попадает (решение 8).
- Синтаксис языка этот план не меняет. Если работа упрётся в язык, варианты выносятся мейнтейнеру
  отдельно.

## 8. Риски

| Риск                                                                    | Что делаем                                                                                          |
| ----------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| Свечение на canvas тормозит на слабых телефонах                         | Замер на этапе 1. Запасной режим: меньше слоёв свечения, без пыли.                                  |
| Порядок ходов в потоках не определён, записанная трасса нестабильна     | Детерминированная запись при сборке; тест сравнивает трассу с примером.                             |
| Неясно, какая горутина сделала ход, если поток держит несколько вызовов | В режиме трассировки одна горутина на поток. Задачи одного потока различаем по имени функции.       |
| Prerender ждёт страницу, а сцена анимируется бесконечно                 | Первый кадр детерминирован; проверить ожидание готовности в `scripts/prerender.ts` на этапе 1.      |
| Canvas-код на Rook окажется неудобным                                   | Это находка для языка: записать, что мешало. На TypeScript переходим только по решению мейнтейнера. |
| Объём текста на двух языках (подписи, врезки, задачи)                   | Подписи ходов собираются из шаблонов по типу события; ручной текст только там, где шаблона мало.    |
| Скринридер не может прочитать сцену                                     | Подпись хода в `aria-live`, управление с клавиатуры, весь текст раздела под сценой.                 |

## 9. Решения

Мейнтейнер принял их 11 ноября 2026 года (этап 0). Невыбранное записано, чтобы не выбирать заново.

1. **Где живёт сцена:** в шапке раздела гайда, адреса не меняются. Не выбрано: отдельная страница
   «Тур» со своим текстом; это вдвое больше текста на двух языках.
2. **Шрифты:** Geist и Geist Mono остаются, для заголовков добавляется один акцидентный шрифт (в
   прототипе это Unbounded). Не выбрано: сменить всё, как в прототипе (Onest, JetBrains Mono).
3. **Язык кода сцены:** Rook. Не выбрано: TypeScript, как редактор в `site/src/editor/`.
4. **Откуда трасса знает строку кода:** опция компилятора `trace`. Не выбрано: стек вызова и
   source map.
5. **Трассировка и roadmap:** трассировка сразу делается как основа «Phase 3 — debugging
   goroutines», но не объявляется публичным API до 1.0.
6. **Правка кода на сцене:** живые числа и кнопка «Открыть в песочнице». Полный редактор в
   карточке — позже, если понадобится.
7. **Порядок:** главная идёт первой. Её первый экран получает сцену сразу после пилота, внутри
   этапа 1, потому что главную посетитель видит первой; общий стиль остальных страниц (остаток
   этапа 3) по-прежнему идёт раньше остальных сцен (этап 4).
8. **Ветка:** работа идёт в ветке `site-redesign` и вливается в `main` по этапам.

## 10. Чек-лист: добавить сцену разделу

1. Пример раздела лежит в `site/examples/` и `site/examples/ru/` и компилируется.
2. Трасса примера записывается при сборке; в ней есть все события, которые нужны сцене.
3. Если нужны новые события — рантайм и тесты рантайма.
4. Если нужны новые фигуры или движения — сначала прототип, потом файл в `site/src/stage/`.
5. Подписи ходов в строках обоих языков.
6. `<Stage>` в разделе обоих языков.
7. Тест состояния по T для новой трассы.
8. `npm run check`, `npm run site:build`, просмотр на десктопе, на телефоне и с
   `prefers-reduced-motion`.
