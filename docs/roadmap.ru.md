# Rook — путь к 1.0

[English](roadmap.md) · **Русский**

Rook сейчас в версии 0.x: язык работает, на нём написан сайт, но спецификация — черновик и ещё
может меняться. Цель — **1.0: язык для продакшна**, со стабильным ядром и инструментами, которых
ждёт команда. Здесь сказано, где Rook сейчас, чего не хватает и в каком порядке это появится. Тот же
план есть на сайте: <https://qwern-9876r.github.io/RookLang/ru/roadmap/>.

## Куда идёт Rook

Rook не пытается стать более широким TypeScript. Его место — **настоящие потоки в браузере и в Node
под проверкой компилятора и UI без фреймворка, на языке, который компилируется в читаемый
JavaScript, который можно оставить себе.** Каждая фаза ниже укрепляет это место.

**Новый синтаксис приходит из списка «Язык к 1.0» ниже,** каждая часть — так, как решит
мейнтейнер. Остальные идеи идут в «Не входит в v0» [спецификации](spec.ru.md) и ждут 1.0.

## Rook сегодня

### Что уже есть

| Опасение                                     | Как на самом деле                                                                                                                                                                                               |
| -------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Горутины — эмуляция на event loop            | `go f(x)` запускает `f` на другом потоке, в Web Worker или в worker thread Node. Внутри потока каналы и `select` работают на его event loop, как `async`-код.                                                   |
| Гонки данных, как в Go                       | То, что уходит в другой поток, копируется (`structuredClone`) или переносится через `transfer(x)`, и компилятор проверяет, что это возможно. Память общая только через созданный для этого `SharedArrayBuffer`. |
| Рантайм увеличивает бандл                    | Модуль импортирует из `rooklang/runtime` только функции, которые использует его код; программа без каналов, горутин и разметки не импортирует ничего. Весь рантайм — около 19 КБ в gzip, до минификации.        |
| Нет библиотек                                | Rook импортирует любой JS-модуль и берёт типы из деклараций TypeScript (`.d.ts`, `@types/*`): библиотеки Rook — это библиотеки npm.                                                                             |
| Rook-компонент не вставить в React или Vue   | `@html-tag` делает компонент веб-компонентом, custom element, который React, Vue, Svelte и обычный HTML используют как любой другой.                                                                            |
| Код на TypeScript не может использовать Rook | `rook build` пишет `.d.ts` рядом с каждым `.js`.                                                                                                                                                                |
| Отладка вслепую                              | Source maps: стектрейсы, в горутинах тоже, и отладчики показывают строки `.rk`-файла.                                                                                                                           |
| Сборка и тесты                               | Плагин для Vite `rooklang/vite`; Vitest запускает код на Rook, горутины тоже.                                                                                                                                   |

### Чего ещё нет

- **Стабильности.** Спецификация помечает экспериментальные разделы, но компилятор пока не
  предупреждает об устаревших формах.
- **Редактора.** Расширение VS Code показывает ошибки при наборе, дополняет и предлагает
  исправления, но не умеет hover, переход к определению, поиск использований, переименование и
  outline.
- **Командной строки.** Есть `rook build` и `rook run`; нет форматтера, нет `check` для CI, нет
  шаблона проекта.
- **Отладки горутин.** Дедлок не сообщается, оставшаяся ждать горутина не видна, у воркеров в
  DevTools нет имён.
- **Цифр.** Нет бенчмарков каналов и горутин против обычного JS, и нет их в CI.
- **TypeScript под Vite.** Плагин Vite не пишет `.d.ts`, поэтому `.ts`-файл, импортирующий там
  `.rk`-модуль, видит `any`.
- **Комментариев в выводе.** Сгенерированный JS сохраняет имена и структуру исходника, но не его
  комментарии.

### Без привязки

Rook компилируется в читаемый JavaScript с теми же именами и структурой. Проект может один раз
собрать свои `.rk`-файлы через `rook build` и дальше жить на JS. Остаётся только импорт
`rooklang/runtime` в коде, где есть каналы, горутины или разметка: это обычный JS под лицензией MIT,
его можно оставить зависимостью или скопировать в проект. Это обещание языка, и руководство
показывает, как это сделать (раздел «Rook в существующем проекте»).

### Фаза 1 — стабильность _(идёт)_

- [CHANGELOG.ru.md](../CHANGELOG.ru.md). В 0.x минорная версия может ломать код, патч — никогда.
  _(сделано)_
- Каждый раздел спецификации помечен **stable** или **experimental**. Экспериментальное может
  меняться в любом релизе, стабильное — только через устаревание. _(сделано)_
- Устаревание: старая форма работает ещё хотя бы одну минорную версию с предупреждением, которое
  показывает новую форму, потом удаляется.
- Снимки сгенерированного кода для примеров сайта и `examples/`, чтобы каждое изменение вывода было
  видно в диффе. _(сделано: `tests/output/`)_
- Комментарии исходника в сгенерированном коде, чтобы JS, который остаётся у проекта, был
  документирован.
- Решены открытые вопросы [components.ru.md](components.ru.md): порог встраивания остаётся
  константой, а имена `@keyframes` — глобальными. _(сделано)_ Остальное — в «Язык к 1.0».

### Язык к 1.0

1.0 должна быть настолько полной, насколько можно. Каждый пункт сначала решает мейнтейнер, потом
он реализуется; открытые перечислены в «Ещё не решено» [components.ru.md](components.ru.md).

- Ключи списков в разметке: `{for todo in todos with key todo.id { ... }}`. _(решено)_
- Объединение интерфейсов сужается по полю литерального типа: `if d.kind == "courier"` даёт
  `d.address`, а `{ kind: "pickup", shop: "..." }` подходит к объединению.
- `derived` из нескольких операторов.
- Объединение декораторов и `public ref` в декораторах.
- Компонент, который возвращает `null` для обёртки.
- Ref в `{if}`, `{switch}` и `{for}` и один ref в нескольких `return`.
- `rook build --explain`: где компилятор не встроил компонент или добавил прокси, и почему.
- CSS компонентов в отдельном файле и класс стиля только на тех элементах, с которыми могут
  совпасть его селекторы.

### Фаза 2 — инструменты

- Языковой сервер: hover с типом, переход к определению, поиск использований, переименование,
  подсказка параметров, символы документа.
- `rook fmt`: один стиль без настроек, как `gofmt`; и форматирование в редакторе.
- `rook check`: только проверка типов, для CI и pre-commit-хуков.
- `rook init`: новый проект с Vite, Vitest и настройками VS Code.
- `.d.ts` для `.rk`-модулей под плагином Vite.

### Фаза 3 — отладка горутин

- Дедлоки: когда все горутины ждут на каналах и ни один таймер не может их разбудить, программа
  останавливается с ошибкой, где сказано, где ждёт каждая.
- `rook run --trace`: при завершении программы — живые горутины и то, чего ждёт каждая.
- Воркеры названы по функции горутины, и DevTools показывает эти имена.

### Фаза 4 — производительность

- Бенчмарки в `bench/`: каналы, `select`, горутины, `go for` и обновления разметки против тех же
  программ, написанных на JS вручную. Цифры на сайте и прогон в CI, который падает при регрессии.
- Оптимизации сгенерированного кода — только там, где бенчмарк показал необходимость. Минификация —
  работа бандлера.

## 1.0

Rook станет 1.0, когда:

- спецификация перестанет быть черновиком: её ядро стабильно, а устаревание работает как описано;
- всё из «Язык к 1.0» сделано;
- в языковом сервере есть навигация и переименование; есть `rook fmt`, `rook check` и `rook init`;
- дедлоки сообщаются, а оставшиеся живыми горутины видны;
- бенчмарки идут в CI, а их цифры есть на сайте;
- руководство показывает, как внести Rook в проект и как уйти с него.
