# Список изменений

[English](CHANGELOG.md) · **Русский**

Что изменилось в каждой версии `rooklang`: язык, компилятор, рантайм и расширение VS Code. Путь к
1.0 описан в [docs/roadmap.ru.md](docs/roadmap.ru.md).

**Версии до 1.0.** Минорная версия (0.4.0) может сломать код, который раньше компилировался, и
говорит, как его поменять, в разделе **Ломающие изменения**. Патч (0.3.5) никогда не ломает: он
только добавляет и исправляет.

## 0.4.0 — 2026-10-29

### Ломающие изменения

- `mount` пишется без скобок, как `effect`: `mount { ... }`. `mount() { ... }` — ошибка, которая
  показывает новую запись.
- `mount` убирает за собой через `defer`, как эффект, и ничего не возвращает: пишите
  `defer clearInterval(timer)` вместо `return () => clearInterval(timer)`. `defer f(x)` берёт `x`
  сразу; для значения, которое появится позже, `defer { editor?.dispose() }` читает его при
  выполнении.

- Публичный член декоратора читают как `@visible.shown`, без `get`: `get(@visible.shown)` теперь
  ошибка, которая показывает новую запись. Декораторы экспериментальные, поэтому старая запись не
  сохраняется. Пишите `@visible.shown` везде, и в разметке тоже: `{if @visible.shown { ... }}`.

### Добавлено

- Состояние модуля (экспериментально): `state items []Item = []` или `export state` на верхнем
  уровне модуля делят его компоненты. Компоненты, которые его читают, обновляются, когда оно
  меняется где угодно в модуле, в том числе через имена, которые указывают внутрь него
  (`for item in items`); они слушают, пока они на странице. Другие модули его читают и меняют только
  функциями его модуля: `items.push(x)` там — ошибка, которая это подсказывает.
- Связанные свойства (экспериментально): `comp Drawer(bind open bool = false)` меняет `open` как
  своё состояние, а `<Drawer bind:open={menu} />` записывает изменения, в том числе на месте, в
  `menu` родителя. Без `bind:` свойство — собственное состояние компонента.
- `class` принимает список классов, `class={[styles.tab, active ? styles.active : null]}`: `null` и
  пустые строки выпадают.
- `bool` в `aria-*` и других атрибутах без DOM-свойства записывается как `"true"` или `"false"`,
  как ждёт ARIA; теперь это описано и проверено тестом.

- Декоратор может включать другие: `dec card(title string) includes framed(title), likes { ... }`
  применяет их вместе с собой, выше своего тела, а их аргументы видят его параметры. Компонент
  читает их публичные члены через него, `@card.count`; `@card` считается применённым `@likes` — для
  `needs` и для повторного применения. Экспортированный декоратор пока не может включать другие.
- `public ref` в декораторе: компонент читает элемент обёртки как `@framed.box`. Сам ref только для
  чтения, его элемент — нет: `@framed.box.title = "Card"`.
- `derived` из нескольких операторов — блок, который возвращает значение:
  `derived summary string { ...; return text }`. Тип можно не писать, тогда он выводится из
  `return`. В JS блок становится функцией, которую вызывают сначала и в обновлениях того, что он
  читает; присвоить в нём состояние — ошибка. `{` после имени `derived` теперь начинает блок,
  поэтому объектный тип там пишут в скобках: `derived p ({ x number }) = ...`.
- Tagged unions (экспериментально): сравнение метки, поля с литеральным типом у каждого члена
  union, сужает union. После `if d.kind == "courier"` можно читать поля `Courier`, и так же в
  `else`, после ветки с `return`, в `switch d.kind` и в `{if}` и `{switch}` разметки. Объектный
  литерал там, где ожидается такой union, проверяется как член, который выбирает его метка:
  `{ kind: "pickup", shop: "Main st." }` подходит к `Pickup | Courier`, а вид, которого нет ни у
  одного члена, — ошибка со списком видов.
- Пути полей с данными от переменной, параметра, `state`, `derived` или `const` модуля сужаются
  так же, как переменная: `if user.boss != null` даёт `user.boss.name` без промежуточной `const`;
  `typeof` и `instanceof` их тоже сужают. Присваивание пути, его начала или его метки сбрасывает
  сужение, присваивание другого поля — нет; геттеры, `a[i]` и `?.` путями не считаются. Подсказка для `<page.other />`, который
  может быть null, теперь показывает `{if page.other != null { <page.other /> }}`.
- Ключи списков в разметке: `{for todo in todos with key todo.id { ... }}` находит блоки заново по
  ключу, так что список, заново загруженный с сервера, сохраняет свои блоки и состояние компонентов
  в них.
- Браузерный компилятор, которым пользуется песочница, знает `AbortController`, `AbortSignal` и
  `ImageData` и как типы: `signal AbortSignal` там компилируется.
- Расширение VS Code проверяет файл тем `rooklang`, который установлен рядом с ним, так что редактор
  показывает ошибки той версии, которую запускает `rook build`; в недоверенной рабочей области и без
  установленного пакета — своей копией. Строка состояния показывает, какой компилятор проверил файл.
- [docs/roadmap.ru.md](docs/roadmap.ru.md): где Rook сейчас и путь к 1.0, и что к тому времени
  должно быть в языке.

### Исправлено

- Ошибка `decode` для union называет член, чья метка подошла: `{ "kind": "square" }` для
  `Circle | Square` даёт `side: missing`, а не `kind: expected "circle", got "square"`. Метка, которая
  не подошла ни к одному члену, перечисляет их все: `kind: expected "circle" | "square", got "oval"`.
- Литеральный тип или их объединение, `type Status "shown" | "aborted"`, можно передать в атрибут
  без DOM-свойства, `data-status={status}`.
- С `runtime: "inline"`, как в песочнице, функция программы с тем же именем, что у функции
  рантайма, например `check`, больше её не подменяет.

## 0.3.4 — 2026-10-26

### Добавлено

- `decode<T>(json)`: проверяет JSON снаружи по типу, когда программа работает.
- `try` как выражение: то, что бросает JS, становится значением ошибки.
- `error(msg, err)` оборачивает ошибку, как `%w` в Go.
- `signal(...)`, `done(abortSignal)` и `abortSignal(ch)`: сигналы процесса и отмена как каналы.
- Топики, `topic<T>(name)`: значения между вкладками сайта.
- `for` по асинхронным итерируемым: потоки Node, `readline`, курсоры.
- `data class`: экземпляры, которые уходят в горутины вместе со своим классом и методами.
- Геттеры и сеттеры, `readonly`, абстрактные классы, `if` с инициализатором, метки, литералы
  регулярных выражений.
- Source maps: стектрейсы, в горутинах тоже, показывают строки `.rk`-файла.
- `rook run --watch`: запускает программу заново, когда меняется её файл.
- Горутины работают под Vitest, который тестирует `.rk`-модули с плагином Vite.
- Расширение VS Code дополняет имена, которые экспортируют другие `.rk`-файлы пакета, и добавляет
  их импорты, а для неопределённого имени предлагает исправление, которое его импортирует.

### Исправлено

- Массив, строку или `Set` можно передать туда, где `.d.ts` ждёт `Iterable<T>`.
- Параметры типа кортежа `[K, V]` из `.d.ts` выводятся по позиции: `new Map([["a", 1]])` — это
  `Map<string, number>`.

## 0.3.3 — 2026-10-18

### Ломающие изменения

- В `const user, err = load(id)` функции с `(User, error)` значение `user` имеет тип `?User`, пока
  не проверен `err`: такая функция теперь может вернуть `return null, err`. Проверяйте ошибку раньше
  значения: `if err != null { return }`.

### Изменено

- `go for` делит массив на четыре части на процессор, каждую — первому свободному воркеру.
- `for i, x in items` по массиву идёт по индексам, а не по парам `entries()`: так быстрее.

### Исправлено

- `for i, c in s` по строке нумерует её символы, а не бросает `TypeError`.
- Воркеры `rook run` больше не загружают компилятор.

## 0.3.2 — 2026-10-17

### Ломающие изменения

- Скомпилированный код импортирует рантайм из `rooklang/runtime`, а не держит его в каждом модуле,
  так что `rooklang` — зависимость проекта, а не только сборки: `npm install rooklang`.

### Добавлено

- Очереди: `queue T`, создаются через `queue<T>()` и `queue<T>(items)`.
- Потоки и каналы: `chan(stream)` и `stream(ch)`.
- Расширение VS Code, которое публикуется из CI.

Более ранние версии — в истории репозитория.
