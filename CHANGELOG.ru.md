# Список изменений

[English](CHANGELOG.md) · **Русский**

Что изменилось в каждой версии `rooklang`: язык, компилятор, рантайм и расширение VS Code. Путь к
1.0 описан в [docs/roadmap.ru.md](docs/roadmap.ru.md).

**Версии до 1.0.** Минорная версия (0.4.0) может сломать код, который раньше компилировался, и
говорит, как его поменять, в разделе **Ломающие изменения**. Патч (0.3.5) никогда не ломает: он
только добавляет и исправляет.

## 0.7.0 — 2026-11-09

Что нашёл перевод HTTP API Breadcast на серверные компоненты (`rook-0.6-report.md`).

### Ломающие изменения

- Классы рантайма после `$$` начинаются со строчной буквы, как его остальные имена: `$$channels`,
  `$$topics`, `$$deque`, `$$safeHtml`, `$$answer` вместо `$$Channel`, `$$Topic`, `$$Queue`,
  `$$Html`, `$$Answer`. Компонент с именем `Queue`, `Channel`, `Topic`, `Html` или `Answer` — это
  `$$Queue` в JS, и он занимал имя рантайма, так что его модуль не загружался. Код, собранный
  прежней версией, собирается заново этой.

### Добавлено

- Обёртка декоратора на сервере, которая принимает `Content<T>`,
  `return (page Content<Html | Response>) => ...`, получает тело компонента как функцию и сама его
  вызывает, так что решает, выполнять ли тело, и ловит то, что оно бросило: граница ошибок,
  `@fallback`, — декоратор, написанный на Rook. Обёртка на сервере может ждать.
- `route("/users/:id", UserPage)` из `rooklang/server` даёт `Route<T>`, чей `match(pathname)`
  даёт страницу с параметрами пути в свойствах или null. Компилятор проверяет параметры
  литерального пути по свойствам страницы в обе стороны.
- `for i in 0..n` перебирает числа от 0 до n, не включая n; конец вычисляется один раз. Цикл
  компилируется в цикл JS, а `{for}` разметки берёт массив чисел.
- Параметр декоратора с `public` — его публичный член:
  `dec http(public request Request, public ip string)`, читается как `@http.request`.
- `handler(App, (request, server) => props)` даёт корню свойства каждого запроса, с одним-двумя
  значениями, которые платформа передаёт после запроса, как сервер `Bun.serve`. Их типы приходят из
  места, куда идёт функция `handler`, из `.d.ts` `Bun.serve`, или пишутся; она даёт
  `Promise<Response>`. `props` у `serve` тоже может быть такой функцией, она получает
  `IncomingMessage` из `node:http`, а `serve` возвращает его `Server`.
- Аргументы декораторов компонента на сервере читают то, что ему нужно:
  `@guard(@api.secret) comp Page() needs api`.
- Компонент подходит к типу, у которого в конце больше свойств: тег их передаёт, а он не
  принимает, `Health()` подходит к `comp(id string)`. Компонент-функция получает элемент ref и
  функции `bind:` как `this`, `$$Card.call({ $$root: el }, title)`, а не после свойств.
- Дженерик-компонент на сервере выводит тип-параметры и из свойств:
  `<List items={[1, 2]} render={n => String(n)} />`.
- `new Promise(...)` без объявленного типа выводит, что он даёт, из вызовов `resolve`:
  `new Promise(resolve => resolve(1))` — это `Promise<number>`. `resolve`, который не вызывается
  или передаётся дальше, `new Promise(resolve => setTimeout(resolve, 5))`, даёт `Promise<void>`.
- Литерал функции берёт типы параметров из единственной функции объединения — так `props` у `serve`
  бывает объектом или функцией.
- `class` принимает `?string`, `class={look == "" ? null : look}`: null оставляет элемент без
  классов, и в браузере тоже, где `className = null` дал бы класс "null".
- `indexOf`, `lastIndexOf` и `includes` у массива принимают, откуда начать поиск, а `fill` —
  начало и конец.

### Исправлено

- Гард с `needs` у компонента из таблицы модуля, `const PAGES = [Page]`, сообщал, что публичные
  члены нужного ему декоратора не публичные: теперь нужные декораторы проверяются раньше него.
- `try` детей серверного компонента, `try await children()` границы ошибок, превращал `Response`
  снизу в ошибку `Error("[object Object]")`; теперь он всплывает дальше.
- Псевдоним инстанцированного дженерик-класса, импортированный из другого модуля,
  `type NumberBox Box<number>`, требовал аргументы типа; `.d.ts` называет такие псевдонимы по имени,
  так что модуль, который импортирует `NumberBox` без `Box`, — правильный TypeScript, и для
  интерфейсов тоже.
- Параметр или имя декоратора, совпадающее с публичным членом включённого им декоратора, давали в
  компоненте одну переменную дважды; теперь это ошибка, которая просит переименовать одно из них.

## 0.6.0 — 2026-11-06

Компоненты на сервере: разметка и компоненты браузера пишут и бэкенд. Это экспериментальная часть,
она может измениться в любом релизе до 1.0; концепция с обоснованиями решений и тем, что ещё не
решено, — в [docs/server.ru.md](docs/server.ru.md).

### Добавлено

- `"rook": { "markup": "html" }` в `package.json` делает разметку строкой HTML типа `Html`: текст и
  атрибуты экранируются, атрибуты проверяются, как в браузере, а `<html>` получает doctype. То, что
  есть только у страницы, — `onClick`, `bind:`, `ref`, `state` и `mount`, — ошибка с подсказкой.
  Сервер в одном репозитории с браузерным кодом получает свой `package.json`.
- Серверные компоненты — асинхронные функции: в теле можно писать `await`, тег — результат
  компонента, которого дождались, а компоненты, стоящие рядом в разметке, рендерятся одновременно.
- Серверный компонент возвращает любое значение; тип выводится или пишется после свойств,
  `comp Users() []User`. `Response` среди детей разметки всплывает и становится ответом на запрос;
  остальные компоненты всё равно доходят до конца, и их `defer` выполняется.
- Дети ленивые, `Content<T>`: функция, которая рендерит их при вызове. У компонентов есть параметры
  типа, `comp Logger<T>(children Content<T>) T`, они выводятся из детей тега, а у типа компонента
  есть результат, `comp(id string) Html`.
- Декораторы на сервере могут ждать (`await`), ранний `return` в их теле — guard, который отвечает
  вместо компонента, а обёртка берёт и отдаёт значение любого типа.
- `needs` у компонента, `comp Header() needs session`, берёт `@session` у компонента выше в дереве
  запроса, так же как декоратор, которому нужен другой. Там, где компонент использован по имени,
  компилятор проверяет, что такой есть.
- `rooklang/server`: `handler(App)` — функция из `Request` в `Response` для Bun, Deno и Workers,
  `serve(App, { port })` запускает её на `node:http`, `reply(value, { status, headers })` делает
  ответ из значения, а `html(text)` помечает доверенный текст как HTML. Ответ делается из значения
  корня: `Response` как есть, `Html` как `text/html`, строка как текст, `null` как 404, остальное
  как JSON.
- `rook run`, плагин Vite и плагин Bun берут `rooklang/server` у того компилятора, который
  запущен, как и `rooklang/runtime`.
- Браузерный компилятор принимает `{ markup: "html" }` и знает `Request`, `Response` и `Headers` как
  типы без `lib.dom`.
- Расширение VS Code подсвечивает `needs` после результата компонента,
  `comp Users() []User needs session`.

### Сайт

- Раздел гайда «Компоненты на сервере» с двумя примерами: блог с макетом, всплывающим 404 и JSON, и
  сессия, guard и обобщённый логгер.
- Сервер сайта, `site/server/main.rk`, написан на серверных компонентах.
- Программа сайта, которая импортирует `rooklang/server`, компилируется с разметкой как HTML.

## 0.5.0 — 2026-10-31

Что нашла команда, которая пишет на Rook браузерную игру с Bun и Vite: чего не хватало и что не
работало.

### Ломающие изменения

- Компонент не меняет несвязанное свойство ни присваиванием, ни на месте: `todo.done = true`,
  `bind:value={todo.title}` и `items.push(x)` для свойства — ошибки, потому что объект принадлежит
  родителю, а его разметка об изменении не знала. Объявите свойство связанным,
  `comp TodoItem(bind todo Todo)`, и передайте его через `bind:todo={todo}`; теперь так можно
  связать и элемент цикла `{for}`.
- `export const Rows = Inner` для компонента без типа — ошибка: его `.d.ts` терял свойства.
  Пишите `export { Rows } from "./rows.rk"` или дайте константе тип компонента.

### Добавлено

- Значения по умолчанию у параметров функций, методов, конструкторов, литералов `func` и стрелочных
  функций, как у свойств компонентов: `func greet(name string = "you", times = 1)`.
- Остаток аргументов, `func log(level string, ...parts []any)`, и в типах функций,
  `func(string, ...[]any)`.
- Теговые шаблоны, `` sql`select * from users where id = ${id}` ``, которые проверяются по
  параметрам тега.
- `export { Row, Rows } from "./rows.rk"` и `export * from "./rows.rk"` — с компонентами,
  декораторами и состоянием.
- Деструктуризация объектов в `const` и `let`: `const { name, size: bytes, ...rest } = file`.
- Методы в объектных литералах: `{ fetch(req Request) Response { ... } }`.
- `x!` считает значение не `null`, как в TypeScript.
- `void` — для `Promise<void>` в интерфейсах и обобщённых типах, и `never` — результат функции,
  которая не возвращается; её вызов сужает типы, как `throw`, в том числе `process.exit(1)`.
- `bind:item={item}` для элемента цикла `{for}`: изменения на месте обновляют список, а новое
  значение заменяет в нём элемент.
- Импорты `.rk`- и `.ts`-модулей по алиасам из `package.json` (`"imports"`, `#ui/button.rk`) и
  `tsconfig.json` (`"paths"`, `@/ui/button.rk`) типизированы и собираются с `.js`.
- Условное выражение можно переносить, начиная строки с `?` и `:`.
- `func(a, b number) number` группирует параметры типа функции, как в Go.
- Объектный тип — результат функции, если за ним идёт тело: `func names() { [string]: string } { ... }`.
- `type` — ключевое слово только перед именем типа в начале оператора: переменные, параметры и
  поля можно называть `type`.
- В npm-пакете есть список изменений.

### Исправлено

- Функция компонента, которая меняет состояние и которую разметка передаёт дочернему компоненту,
  `act={copy}`, или которую вызывает переданная ему стрелка, `act={() => show("x")}`, обновляет
  разметку: её принимали за код отрисовки, который ничего не обновляет.
- Импорт `describe` и `it` из Vitest переполнял стек, а затем проверялся две минуты: типы
  `.d.ts`, которые ссылаются сами на себя, подставляются, когда используются. Длинный тип внутри
  другого сообщения печатают как `{ ... }`.
- Типы `@types/bun`: глобальный `Bun` и модуль `bun` были без типов, а в
  `Bun.serve({ fetch: req => ... })` у `req` теперь есть тип.
- Колбэк, у которого в `.d.ts` результат `any` или `void | T`, `ws.onopen = () => { ... }`, и
  функция с результатом `any` могут закончиться без `return`.
- Строка, которая кончается на `>` аргументов типа, `votes Map<string, number>`, завершает
  объявление.
- Поле класса видит константу своего модуля с записанным типом или литеральным значением,
  `limit = LIMIT`.
- Понятные ошибки для `` `${x++}` ``, аргументов типа в вызове, `load<number>(1)`, и нескольких
  результатов условного выражения, `a ? two() : one()`.

### Сайт

- Сайт выкладывается с каждым выпуском в npm, а не с каждым пушем в `main`, поэтому описывает ту
  версию, которую ставит `npm install`.

## 0.4.0 — 2026-10-29

### Ломающие изменения

- `mount` пишется без скобок, как `effect`: `mount { ... }`. `mount() { ... }` — ошибка, которая
  показывает новую запись.
- `mount` убирает за собой через `defer`, как эффект, и ничего не возвращает: пишите
  `defer clearInterval(timer)` вместо `return () => clearInterval(timer)`. `defer f(x)` берёт `x`
  сразу; для значения, которое появится позже, `defer { editor?.dispose() }` читает его при
  выполнении.

- Публичный член декоратора читают как `@visible.shown`, без `get`: `get(@visible.shown)` теперь
  ошибка, которая показывает новую запись. Декораторы экспериментальные, поэтому старая запись не
  сохраняется. Пишите `@visible.shown` везде, и в разметке тоже: `{if @visible.shown { ... }}`.

### Добавлено

- Состояние модуля (экспериментально): `state items []Item = []` или `export state` на верхнем
  уровне модуля делят его компоненты. Компоненты, которые его читают, обновляются, когда оно
  меняется где угодно в модуле, в том числе через имена, которые указывают внутрь него
  (`for item in items`); они слушают, пока они на странице. Другие модули его читают и меняют только
  функциями его модуля: `items.push(x)` там — ошибка, которая это подсказывает.
- Связанные свойства (экспериментально): `comp Drawer(bind open bool = false)` меняет `open` как
  своё состояние, а `<Drawer bind:open={menu} />` записывает изменения, в том числе на месте, в
  `menu` родителя. Без `bind:` свойство — собственное состояние компонента.
- `class` принимает список классов, `class={[styles.tab, active ? styles.active : null]}`: `null` и
  пустые строки выпадают.
- `bool` в `aria-*` и других атрибутах без DOM-свойства записывается как `"true"` или `"false"`,
  как ждёт ARIA; теперь это описано и проверено тестом.

- Декоратор может включать другие: `dec card(title string) includes framed(title), likes { ... }`
  применяет их вместе с собой, выше своего тела, а их аргументы видят его параметры. Компонент
  читает их публичные члены через него, `@card.count`; `@card` считается применённым `@likes` — для
  `needs` и для повторного применения. Экспортированный декоратор пока не может включать другие.
- `public ref` в декораторе: компонент читает элемент обёртки как `@framed.box`. Сам ref только для
  чтения, его элемент — нет: `@framed.box.title = "Card"`.
- `derived` из нескольких операторов — блок, который возвращает значение:
  `derived summary string { ...; return text }`. Тип можно не писать, тогда он выводится из
  `return`. В JS блок становится функцией, которую вызывают сначала и в обновлениях того, что он
  читает; присвоить в нём состояние — ошибка. `{` после имени `derived` теперь начинает блок,
  поэтому объектный тип там пишут в скобках: `derived p ({ x number }) = ...`.
- Tagged unions (экспериментально): сравнение метки, поля с литеральным типом у каждого члена
  union, сужает union. После `if d.kind == "courier"` можно читать поля `Courier`, и так же в
  `else`, после ветки с `return`, в `switch d.kind` и в `{if}` и `{switch}` разметки. Объектный
  литерал там, где ожидается такой union, проверяется как член, который выбирает его метка:
  `{ kind: "pickup", shop: "Main st." }` подходит к `Pickup | Courier`, а вид, которого нет ни у
  одного члена, — ошибка со списком видов.
- Пути полей с данными от переменной, параметра, `state`, `derived` или `const` модуля сужаются
  так же, как переменная: `if user.boss != null` даёт `user.boss.name` без промежуточной `const`;
  `typeof` и `instanceof` их тоже сужают. Присваивание пути, его начала или его метки сбрасывает
  сужение, присваивание другого поля — нет; геттеры, `a[i]` и `?.` путями не считаются. Подсказка для `<page.other />`, который
  может быть null, теперь показывает `{if page.other != null { <page.other /> }}`.
- Ключи списков в разметке: `{for todo in todos with key todo.id { ... }}` находит блоки заново по
  ключу, так что список, заново загруженный с сервера, сохраняет свои блоки и состояние компонентов
  в них.
- Браузерный компилятор, которым пользуется песочница, знает `AbortController`, `AbortSignal` и
  `ImageData` и как типы: `signal AbortSignal` там компилируется.
- Расширение VS Code проверяет файл тем `rooklang`, который установлен рядом с ним, так что редактор
  показывает ошибки той версии, которую запускает `rook build`; в недоверенной рабочей области и без
  установленного пакета — своей копией. Строка состояния показывает, какой компилятор проверил файл.
- [docs/roadmap.ru.md](docs/roadmap.ru.md): где Rook сейчас и путь к 1.0, и что к тому времени
  должно быть в языке.

### Исправлено

- Ошибка `decode` для union называет член, чья метка подошла: `{ "kind": "square" }` для
  `Circle | Square` даёт `side: missing`, а не `kind: expected "circle", got "square"`. Метка, которая
  не подошла ни к одному члену, перечисляет их все: `kind: expected "circle" | "square", got "oval"`.
- Литеральный тип или их объединение, `type Status "shown" | "aborted"`, можно передать в атрибут
  без DOM-свойства, `data-status={status}`.
- С `runtime: "inline"`, как в песочнице, функция программы с тем же именем, что у функции
  рантайма, например `check`, больше её не подменяет.

## 0.3.4 — 2026-10-26

### Добавлено

- `decode<T>(json)`: проверяет JSON снаружи по типу, когда программа работает.
- `try` как выражение: то, что бросает JS, становится значением ошибки.
- `error(msg, err)` оборачивает ошибку, как `%w` в Go.
- `signal(...)`, `done(abortSignal)` и `abortSignal(ch)`: сигналы процесса и отмена как каналы.
- Топики, `topic<T>(name)`: значения между вкладками сайта.
- `for` по асинхронным итерируемым: потоки Node, `readline`, курсоры.
- `data class`: экземпляры, которые уходят в горутины вместе со своим классом и методами.
- Геттеры и сеттеры, `readonly`, абстрактные классы, `if` с инициализатором, метки, литералы
  регулярных выражений.
- Source maps: стектрейсы, в горутинах тоже, показывают строки `.rk`-файла.
- `rook run --watch`: запускает программу заново, когда меняется её файл.
- Горутины работают под Vitest, который тестирует `.rk`-модули с плагином Vite.
- Расширение VS Code дополняет имена, которые экспортируют другие `.rk`-файлы пакета, и добавляет
  их импорты, а для неопределённого имени предлагает исправление, которое его импортирует.

### Исправлено

- Массив, строку или `Set` можно передать туда, где `.d.ts` ждёт `Iterable<T>`.
- Параметры типа кортежа `[K, V]` из `.d.ts` выводятся по позиции: `new Map([["a", 1]])` — это
  `Map<string, number>`.

## 0.3.3 — 2026-10-18

### Ломающие изменения

- В `const user, err = load(id)` функции с `(User, error)` значение `user` имеет тип `?User`, пока
  не проверен `err`: такая функция теперь может вернуть `return null, err`. Проверяйте ошибку раньше
  значения: `if err != null { return }`.

### Изменено

- `go for` делит массив на четыре части на процессор, каждую — первому свободному воркеру.
- `for i, x in items` по массиву идёт по индексам, а не по парам `entries()`: так быстрее.

### Исправлено

- `for i, c in s` по строке нумерует её символы, а не бросает `TypeError`.
- Воркеры `rook run` больше не загружают компилятор.
