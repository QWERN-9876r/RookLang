# Rook для VS Code

[English](README.md) · **Русский**

Поддержка Rook — языка с семантикой JavaScript, синтаксисом в духе Go и статической
типизацией — для файлов `.rk`: подсветка, ошибки прямо при наборе, автодополнение и автоимпорт.

## Ошибки, автодополнение и импорты

Расширение запускает языковой сервер с компилятором Rook. Пока вы печатаете, он подчёркивает
ошибки и предупреждения, которые напечатал бы `rook build`, и дополняет:

- имена в области видимости: переменные, параметры, функции, классы, компоненты, глобальные имена
  вроде `document` и ключевые слова;
- члены после `.` и `?.` с их типами: у классов (приватные — только внутри класса), интерфейсов,
  объектов, строк, массивов и DOM;
- типы там, где пишется тип: `let user Us|`;
- теги и компоненты в разметке, `<Ca|`, а также свойства компонента или атрибуты и события
  элемента, `<input on|`;
- имена, которые экспортируют другие файлы `.rk` пакета: функции, классы, константы, типы и
  компоненты. Рядом с именем показан путь к файлу, а выбор имени добавляет импорт: в
  `import { ... }` этого файла, если он в модуле уже есть, иначе отдельной строкой после последнего
  импорта.

Для неизвестного имени (`"formatDate" is not defined`, `unknown type "User"`, `unknown component
<Card>`, `unknown decorator @visible`) есть быстрое исправление (`Cmd+.`), которое импортирует его
из каждого файла пакета, где оно экспортируется.

Типы стандартной библиотеки и DOM берутся из lib-файлов TypeScript, которые расширение везёт с собой.
Пакет файла — это папка ближайшего к нему `package.json`, без `node_modules`, `dist`, `build`,
`out`, `coverage` и папок, чьи имена начинаются с точки. Импорты других файлов `.rk` и пакетов с типами проверяются так же, как в `rook build`.
Разметка и компоненты — ошибки, если ближайший `package.json` не включает их через
`"rook": { "markup": true }`, как и для `rook build`.

## Подсветка

Подсвечиваются:

- ключевые слова, объявления `func`, `comp`, `class`, `interface`, `type`, `state` и `mount()`;
- типы в стиле Go: `number`, `[]Todo`, `?User`, имена классов и интерфейсов;
- строки, шаблонные строки с `${...}`, числа, комментарии;
- разметка: теги, компоненты, атрибуты, `on*`, `bind:value`, выражения в `{...}`, а также `if`,
  `for` и `switch` внутри неё.

Ещё расширение настраивает комментарии (`Cmd+/`), закрытие скобок и кавычек и отступ в 4 пробела.

## Установка

Найдите «Rook Language» в панели расширений VS Code или установите его из
[Visual Studio Marketplace](https://marketplace.visualstudio.com/items?itemName=Qwern9876r.rooklang).
VSCodium, Cursor и другие редакторы, которые берут расширения из
[Open VSX](https://open-vsx.org/extension/Qwern9876r/rooklang), найдут его там. Из командной строки:

```sh
code --install-extension Qwern9876r.rooklang
```

Расширение несёт свою копию компилятора, поэтому больше ничего не нужно. Чтобы собирать и запускать
файлы `.rk`, поставьте и компилятор: `npm install --save-dev rooklang`.

## Какой компилятор проверяет файлы

Если `rooklang` установлен в проекте, расширение проверяет файл этой версией: той, что лежит в
ближайшем `node_modules/rooklang` вверх от файла, как его нашёл бы Node. Так редактор показывает
ошибки той же версии, которую запускает `rook build`, а новая версия начинает работать сразу после
установки, без перезагрузки окна. Без установленного `rooklang` расширение берёт свою копию.

В строке состояния видно, каким компилятором проверен открытый файл: `Rook 0.3.4` — установленным,
`Rook (built-in)` — копией расширения; подсказка говорит, где он лежит. В панели вывода «Rook»
написано, какая версия загружена или почему её не удалось загрузить — тогда расширение берёт свою
копию.

Загрузка установленного компилятора запускает код проекта, поэтому в папке, которой VS Code не
доверяет (ограниченный режим), расширение берёт свою копию; оно переключится, как только вы
доверитесь папке.

## Ограничения

Как и в `rook build`, в файле с синтаксической ошибкой видны только синтаксические ошибки: типы
проверяются, когда файл разбирается. Импортируемые файлы `.rk` видны такими, какими они сохранены
на диске.

Подсветка — это грамматика TextMate: она смотрит на текст строки, а не на синтаксическое дерево.
Поэтому:

- `<` считается началом разметки, если перед ним нет значения (имени, `)` или `]`) и сразу после
  него идёт имя тега. `a < b` и `i<n` — сравнения, а `return <div>` — разметка;
- типы узнаются по виду: встроенные (`number`, `string`…) и имена с заглавной буквы. Свои типы со
  строчной буквы (`type id = number`) подсвечиваются как обычные имена.
